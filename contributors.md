# 🤝 Contributor Guidelines

Welcome to Open Project Hub!

This repository is open to developers, students, designers, researchers, creators, and anyone interested in sharing useful projects with the community.

## 🚀 Before You Contribute

Please make sure you:

* Own the project or have permission to publish it.
* Do not submit malicious or harmful software.
* Do not upload passwords, private keys, API keys, tokens, or other secrets.
* Follow the license of third-party code and assets.
* Provide accurate information about your project.
* Follow the repository's Code of Conduct.

## 📁 Project Structure

Create a folder using your project name:

```text
projects/
└── my-awesome-project/
    ├── README.md
    ├── LICENSE
    └── source-code...
```

The project folder should be:

* Descriptive
* Unique
* Easy to read
* Free of unnecessary spaces

Example:

```text
projects/
└── weather-dashboard/
```

## 📝 Project README

Every project should include a README containing, where applicable:

* Project name
* Description
* Features
* Technologies used
* Installation instructions
* Usage instructions
* Screenshots or demo
* Live URL
* Repository URL
* Author/contributors
* License

## 📋 Add Your Project to the List

After adding your project, update:

```text
project-list.md
```

Place your project in the appropriate category.

## 🔀 Pull Request Process

1. Fork the repository.
2. Create a branch.

```bash
git checkout -b add-my-project
```

3. Add your project.
4. Update `project-list.md`.
5. Check your changes.
6. Commit your changes.

```bash
git add .
git commit -m "Add my project"
```

7. Push your branch.

```bash
git push origin add-my-project
```

8. Open a Pull Request.

## ✅ Pull Request Checklist

* [ ] I read `contributors.md`.
* [ ] My project is inside the `projects/` directory.
* [ ] My project has a README.
* [ ] I added my project to `project-list.md`.
* [ ] I have permission to submit this project.
* [ ] I did not include secrets or private information.
* [ ] My links work correctly.
* [ ] My project follows the repository guidelines.
* [ ] I have checked my project for obvious security issues.

## ❌ What We Don't Accept

We may reject or remove projects containing:

* Malware or intentionally harmful code
* Stolen or copyrighted material without permission
* Exposed credentials or private information
* Scam or phishing projects
* Illegal content
* Spam
* Misleading project descriptions
* Projects submitted without permission
* Malicious dependencies or intentionally harmful scripts

## 🔐 Security

If you discover a security vulnerability, do not publicly disclose sensitive details.

Please read [SECURITY.md](SECURITY.md).

## 💡 Quality Matters

Projects don't have to be perfect.

Simple student projects, experiments, prototypes, games, websites, AI projects, libraries, APIs, research projects, and hackathon projects are welcome.

**We care more about learning and sharing than perfection.**

## ❤️ Be Respectful

Treat contributors with respect.

Constructive feedback is encouraged.

Harassment, discrimination, personal attacks, and hostile behavior are not welcome.

See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
